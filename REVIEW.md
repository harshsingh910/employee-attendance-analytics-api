# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Static return `{"status": "ok"}` without checking database connectivity. | Stop or disconnect MongoDB; `/health` still returns 200 instead of required 503. | Added `client.admin.command("ping")` inside a try-catch block; raises HTTP 503 if unreachable. |
| 2 | Startup & `create_employee` (lines 78-85) | No database unique index created on `emp_code`. Duplicate check used naive `find_one` followed by `insert_one`. | Concurrent `POST /employees` requests with identical `emp_code` race and insert duplicates or cause 500 errors. | Created unique index on `employees.emp_code` at startup; handled `DuplicateKeyError` atomically by returning HTTP 409. |
| 3 | `EmployeeIn` (lines 53-60) | Missing schema validations: allowed invalid `emp_code` formats (pattern `^EMP\d{4,6}$` not enforced), unvalidated emails, and failed to reject `shift_start == shift_end`. | `POST /employees` with `shift_start="09:30"`, `shift_end="09:30"` succeeded with 201 instead of 422. Bad formats were accepted. | Added Pydantic field validators and model validator enforcing format regexes and `shift_start != shift_end` (raising 422). |
| 4 | `list_employees` (line 93) | Off-by-one pagination bug: calculated skip as `page * page_size`, skipping the entire first page (`1 * 20 = 20`). | `GET /employees?page=1` skipped the first 20 employees and started at index 20. | Changed skip calculation to `(page - 1) * page_size`. |
| 5 | `list_employees` (line 94) | Unfiltered total count: `total = db.employees.count_documents({})` counted the entire collection regardless of query filters. | `GET /employees?department=Sales` returned the total count across all departments rather than the filtered department count. | Changed to `db.employees.count_documents(q)`. |
| 6 | `list_employees` (line 95) | Missing deterministic sorting: query did not sort by `emp_code` ascending. | Repeated queries returned non-deterministic order depending on insertion order and storage engine. | Added `.sort("emp_code", 1)`. |
| 7 | `compute_late_minutes` (lines 33-37) | Incorrect grace period boundary: `int(...) / 60` truncated seconds before checking `> 10`, so 09:40:01 produced `minutes = 10` and `10 > 10` evaluated to False (returned 0). | Punching in at 09:40:01 for a 09:30 shift returned 0 late minutes instead of 10. | Enforced R2: checked `diff_seconds > 600` strictly, and if true, computed `math.floor(diff_seconds / 60)`. |
| 8 | `compute_work_hours` (line 40) | Used Python's built-in `round()`, which applies Banker's rounding (round half to even) instead of Decimal Half-Up rounding. | A duration of 9.125 hours rounded down to 9.12 instead of 9.13 (R4, R8 require half-up). | Replaced with `Decimal` using `ROUND_HALF_UP` to 2 decimal places. |
| 9 | `compute_overtime` (lines 44-47) | Overnight shifts broken across midnight and missing 30-minute threshold: replaced time on `date_str` without shifting +1 day, and returned any positive minutes without checking >= 30. | Punching out 20 minutes after shift end returned 20 overtime minutes instead of 0. Overnight shifts (22:00-06:00) calculated negative differences. | Added overnight shift check (`shift_end <= shift_start`) to advance shift end to next calendar day; enforced 30-minute minimum threshold before calculating floor minutes. |
| 10 | `punch_in` (lines 104-121) | Concurrency race condition on daily attendance log creation: used `find_one` then `insert_one` without unique compound index on `(emp_code, date)`. | Two concurrent punch-ins for the same employee on the same day both passed and created duplicate daily logs. | Created unique compound index on `(emp_code, date)` on `attendance_logs` at startup; caught `DuplicateKeyError` and returned HTTP 409. |
| 11 | `punch_in` (line 101) | Unhandled missing employee: `emp = db.employees.find_one(...)` without checking `if not emp:`, crashing on `emp["shift_start"]` with `TypeError` (HTTP 500). | `POST /attendance/punch-in` with non-existent `emp_code` produced an unhandled 500 error instead of 404. | Added explicit check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 12 | `list_attendance` (lines 144-150) | In-memory loading and sorting of unbounded dataset: `docs = list(db.attendance_logs.find(q))` loaded entire collection (~100k docs) into memory, sorted in Python, and sliced in Python. Also lacked secondary sort on `emp_code`. | Severe latency and memory exhaustion at 100k documents; arbitrary ordering on matching dates. | Pushed sorting, skip, and limit directly to MongoDB: `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)` backed by compound index `{"date": -1, "emp_code": 1}`. |
| 13 | `list_attendance` (lines 136-141) | Missing date range validation: did not validate that `date_from <= date_to`. | `GET /attendance?date_from=2026-07-10&date_to=2026-07-05` returned 200 with an empty list instead of 422. | Added validation raising HTTP 422 when `date_from > date_to`. |
| 14 | Serialization (lines 85, 119-120, 149) | Leaked internal `_id` as `id` string and failed to serialize BSON dates to integer epoch milliseconds. | Returned `id: "..."` in responses (prohibited by contract) and raw datetime objects that violated OpenAPI schema. | Removed `_id` completely; converted all BSON datetimes (`punch_in`, `punch_out`, `created_at`, `history[].at`) to integer epoch milliseconds. |
| 15 | Timezone & Truncation (lines 82, 102) | Used naive system local time (`datetime.now()`) and unanchored `fromtimestamp()`, mixing naive and aware datetimes, and omitted sub-second truncation (R1). | Running on non-IST machines caused calendar date shifts; sub-seconds were stored instead of truncated whole seconds. | Enforced explicit UTC instants and IST conversions for shift comparisons, with sub-second truncation `(ms // 1000) * 1000` (R1). |

## Examined and Decided Not a Defect

1. **Storing Calendar Dates as `YYYY-MM-DD` Plain Strings:**
   - Examined whether `date` and `joined_on` should be stored as BSON dates or string dates.
   - Decided it is **not a defect**: As explicitly documented in `DATA_MODEL.md` (section 1), calendar dates are intentionally plain strings to avoid timezone coercion and daylight ambiguity.
2. **Missing `half_day` and `history` in Older/Seeded Documents:**
   - Examined why some sample documents omit `half_day` or `history`.
   - Decided it is **not a defect**: Per `DATA_MODEL.md` (sample 9), legacy records may omit these fields. The application correctly treats missing `half_day` as `False` and missing `history` as `[]`.
3. **Absence of Authentication / Authorization:**
   - Examined whether endpoints should have JWT or bearer auth.
   - Decided it is **not a defect**: The official problem statement and OpenAPI specification explicitly specify no authentication for this assignment (`regularized_by` is passed as free text). Adding unsolicited auth would violate the test harness.
